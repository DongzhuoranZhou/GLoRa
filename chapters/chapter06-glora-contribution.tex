\chapter{The GLoRa Contribution}
\label{chap:glora-contribution}

Chapter~5 identified a gap between a benchmark that contains distant information and one that establishes learning of a specified path-aware dependency.
The included paper addresses this gap with GLoRa, the Graph Long-Range dependency benchmark, which generates controlled inductive binary node-classification tasks \cite{zhou2025glora}.
Its contribution is a chain from evaluation threat to design response, guarantee or control, empirical result, and bounded interpretation.
This chapter follows that chain rather than reproducing Paper~I section by section.

\section{From Evaluation Threats to Design Requirements}
\label{sec:glora-motivation}

The first threat inherited from Chapter~5 is that a label may be generated by a long-range rule while the examples still admit a shortcut function.
Real-world long-range benchmarks compare practical performance, but they do not formally control the dependency that every fitting function uses \cite{dwivedi2022long,zhou2025glora}.
High accuracy then shows that a system fits the examples, but not that its prediction uses the intended source-to-target path.
The second threat is an inexpressible target, for which low accuracy cannot distinguish a learning failure from the absence of a fitting function in the model class.
The third threat concerns two distinct forms of fairness: class-distribution fairness requires that positive and negative examples not be separated by an avoidable change in their generation, whereas system-protocol fairness requires systems to be evaluated under a common protocol.
Finally, an accuracy decline is a symptom rather than a diagnosis of over-smoothing, over-squashing, or vanishing gradients \cite{li2018deeper,alon2021bottleneck,glorot2010difficulty}.

GLoRa responds to these threats through the following design requirements \cite{zhou2025glora}.
The target must specify a path-aware relation between a source node and a target node.
The generated examples must prevent the presence or number of holes from serving as a shortcut.
Sufficiently many examples must make every fitting node-classification function rely on the specified dependency, while at least one fitting function remains expressible by the evaluated GNN-based approaches.
Positive and negative examples must come from the same probabilistic generator in the sense defined by Paper~I.
The experiment must vary dependency length under a common protocol and test the traces predicted by each candidate failure mechanism.

The length notation requires care at the outset.
Chapter~3 uses $d$ for the exact length of a witness path $p=(v_0,\ldots,v_d)$.
Paper~I also uses $d$ as the input to the GLoRa generator, but the generator samples exact source-to-target chain lengths between $\lfloor 2d/3\rfloor$ and $d$.
This chapter therefore calls the input the \emph{generator parameter} $d$ and states an exact path or chain length separately whenever the distinction matters.

\section{Task and Construction}
\label{sec:glora-path-aware}
\label{sec:glora-design}
\label{sec:glora-shortcuts}

GLoRa generates examples for inductive binary node classification.
Its inputs are a generator parameter $d\geq 3$ and a label $\mathit{Ans}\in\{\mathrm{True},\mathrm{False}\}$.
The output is a directed graph $G=(V,E,\lambda)$ together with a target node, and every node has a two-dimensional feature vector.
All random draws in the algorithm are uniform and independent unless the construction imposes the stated ordering constraint \cite{zhou2025glora}.

The intended function classifies the target as True if and only if there is a path of length at most $d$ from a source node to the target node such that every non-source node on the path has the required marker.
The source node has feature $(1,y)$, a normal non-source node has feature $(x,1)$, and a hole has feature $(x,0)$.
The filler values $x$ and $y$ are sampled from
\[
  D=[-12,-2]\cup[3,13].
\]
This range keeps the random filler values separate from the binary markers $0$ and $1$.
The source marker identifies the role of the source node, while the second coordinate determines whether a non-source node can belong to a complete path.

Part~A of the generator creates the main source-to-target chain.
Its exact length $k_0$ is sampled from the integers in $\{\lfloor 2d/3\rfloor,\ldots,d\}$, so exact chain length is not fixed by the generator parameter.
The chain begins at the source node and ends at the target node.
For a positive example, every non-source node on this chain is normal.
For a negative example, one non-target intermediate node is made a hole at position $h_0\in\{1,\ldots,k_0-1\}$, sampled uniformly.
In a positive example, the complete main chain is a witness whose exact length is $k_0$, not necessarily $d$.

The naive positive and negative pair would leave a shortcut: the target could be classified by testing whether any hole occurs in the graph.
A global readout, virtual node, or preprocessing step that exposes this graph-wide test could fit the naive examples without using the source-to-target path.
Part~B responds by sampling a number of alternative chains $P_{\mathrm{chain}}\in\{5,\ldots,10\}$.
For each alternative chain, the algorithm samples a scale $k_p\in\{\lfloor 2d/3\rfloor,\ldots,d\}$ and positions $m_p,n_p\in\{1,\ldots,k_p-1\}$ subject to $m_p\leq n_p$.
These positions select attachment points on chains that have already been generated and delimit the fresh segment added between them.
The attachment rule prevents loops and keeps the corresponding source-to-target path length within $\{\lfloor 2d/3\rfloor,\ldots,d\}$.
Every alternative chain receives one hole at a position $h_p\in\{m_p,\ldots,n_p\}$, sampled uniformly.
Holes therefore occur in both classes, and the system is not told which chain is the main chain.

Part~C responds to shortcuts based on the number of holes on a path or in the graph.
The algorithm first samples $R\in\{2,3\}$ and excludes the source and target nodes from the candidate set.
For a negative example, it samples $R$ additional hole placements from that set.
For a positive example, it uses $R+1$ placements and also excludes every intermediate node on the complete main chain.
The extra positive placement compensates for the hole already placed on the negative main chain.
Paper~I states that this step preserves the positive witness and gives positive and negative examples the same distribution over the number of holes \cite{zhou2025glora}.

These construction choices explain how the named shortcut functions are obstructed, but the construction alone is not the universal claim.
Property~(P1), stated next, supplies the guarantee over all fitting node-classification functions when the required sample conditions hold.
The directed construction also has a separate diagnostic consequence because the number of directed source-to-target paths remains bounded independently of $d$.

\section{Guarantees and Controls}
\label{sec:glora-expressibility}

Paper~I states three properties for a benchmark generated at parameter $d$ \cite{zhou2025glora}.
Property~(P1) says that every node-classification function fitting a sufficiently large training sample relies on a dependency of length $d$, subject to the precision and probability qualifications below.
Here, $d$ is both the generator parameter and the guaranteed dependency length; it is not the realised chain length of every example.
Property~(P2) says that there is at least one fitting function that every GNN-based approach considered in Paper~I, including GCNs, can express.
Property~(P3) gives Paper~I's fairness condition: the same probabilistic algorithm generates all examples, with $\mathit{Ans}$ selecting the required class.

Theorem~1 makes the precision, probability, and sample-size qualifications in Property~(P1) explicit.
For every $d\in\mathbb{N}$, every precision $\delta>0$, and every probability $P\in(0,1)$, there exists a sample size $K$.
With probability at least $P$, every node-classification function that fits a sample of $K$ examples, half generated by $\operatorname{GLoRa}(d,\mathrm{True})$ and half by $\operatorname{GLoRa}(d,\mathrm{False})$, relies on a dependency of length $d$ with precision $\delta$ \cite{zhou2025glora}.
The approximate dependency definition measures feature agreement with the maximum norm.
Required matches may differ by at most $\delta$, while each designated contrast differs from the original feature by at least $3\delta$.
The proof sketch uses the finite set of graph structures possible for fixed $d$, their non-zero sampling probabilities, and the bounded continuous feature domain to obtain a sufficiently large $K$.

Property~(P1) is stronger than saying that the intended function generated the labels because it quantifies over every function that fits the sampled examples under the theorem's conditions.
The guarantee remains conditional on $\delta$ and $P$ and on choosing a corresponding sample size $K$.
Paper~I does not report numerical values of $\delta$ and $P$ that connect the experimental sample size to a particular theorem guarantee.
The experimental result therefore cannot be assigned a specific precision or probability guarantee from Theorem~1.

Property~(P2) controls a different threat.
Paper~I uses the results of Barcel\'o et al. to establish that GCNs can express the intended path function and argues that the other evaluated GNN-based approaches are at least as expressive for this purpose \cite{barcelo2020logical,zhou2025glora}.
This is an expressibility result, not a learnability result.
It establishes that suitable parameters exist in the model class, but it does not establish that finite-data optimisation will find them.

Property~(P3) is distinct from fairness across systems in the empirical comparison.
The latter is controlled by using the same generated task, data split, validation procedure, and reporting protocol for the evaluated systems.

\section{Experimental Evidence}
\label{sec:glora-protocol}
\label{sec:glora-main-findings}

The main study varies the generator parameter over $d\in\{3,\ldots,15\}$.
At each value, it generates $5000$ positive and $5000$ negative examples, then splits each class in the ratio $80{:}10{:}10$ into training, validation, and test sets \cite{zhou2025glora}.
The resulting sets contain $4000$ training, $500$ validation, and $500$ test examples from each class.
The task is balanced, so random guessing has expected accuracy $0.5$.
It is also noise-free, which makes accuracy $1.0$ a reasonable target.
Paper~I treats accuracy below $0.8$ as an indication that a system has not effectively learned a function fitting the examples at that generator parameter.

The comparison covers vanilla GNN-based systems, systems targeting over-smoothing, systems targeting over-squashing or vanishing gradients, and graph transformers.
It includes the gated systems that lead the reported results and the three systems later used for diagnostics: GatedGCN, DenseGatedGCN, and 1Drew-GCN.
The transformer group contains GraphTransformer, SAN, and GraphGPS variants.
Paper~I lists every evaluated implementation and hyperparameter setting.

Each system is run five times on every benchmark and trained for at most $300$ epochs or until convergence.
Hyperparameters are validated, and the reported test accuracy is the mean over the five runs.
GNN-based systems use $d+2$ layers, which Paper~I states is sufficient to express the intended function at generator parameter $d$.
The common batch size is $32$.
Training uses AdamW, weight initialisation, gradient clipping, ReLU activations where appropriate, and batch normalisation.
These details are sufficient to interpret the evidence here.
Paper~I gives the exhaustive implementation and search spaces.

The sampled chain bounds make the generator parameter and realised path lengths close but not identical.
For $d=5$, $10$, and $15$, Paper~I reports average source-to-target path lengths of $5$, $9$, and $14$, respectively.
The reported average in-degree remains approximately $2$ at these settings.
These statistics show how the experiment increases realised path length without making $d$ an exact path-length label for every example.

Under this protocol, most evaluated systems show a performance drop before $d$ reaches $9$, and the stronger systems perform poorly after $d=11$ \cite{zhou2025glora}.
GatedGCN, DenseGatedGCN, and ResGatedGCN give the best reported performance, while the transformer-based systems perform poorly even at very short values of $d$.
Paper~I also reports similar performance on the undirected version of the benchmark.
These are protocol-bound observations about the evaluated systems and generated tasks, not universal dependency-length limits.
The decline establishes the empirical symptom that the diagnostic study examines, but accuracy alone does not identify its mechanism.

\section{Diagnostic Evidence}
\label{sec:glora-diagnostics}

The diagnostic study focuses on GatedGCN, DenseGatedGCN, and 1Drew-GCN because they are the best-performing systems in the first three experimental categories.
Each diagnostic tests whether the performance decline is accompanied by the trace predicted by one proposed mechanism, then limits its conclusion to what the selected measurement can show.

\subsection{Over-Smoothing}

The prediction is that complete over-smoothing would make final representations that should remain distinct converge as depth increases \cite{li2018deeper}.
Paper~I measures the one-dimensional final representation of the target node across examples at generator parameters $d=6$ and $d=13$.
Here, $d=6$ is the largest value at which all three systems have accuracy $1$, whereas $d=13$ is the smallest value at which their accuracy is close to $0.5$.
Because the systems use $d+2$ layers, the measured values come from layers $8$ and $15$, respectively.

At $d=6$, the scalar target representations for positive and negative examples are clearly separated.
At $d=13$, the two distributions mix, but the measured values retain substantial standard deviation and do not converge to one value \cite{zhou2025glora}.
Thus, the measurement finds no complete collapse of this scalar across the tested examples.
It does not generally exclude within-graph over-smoothing, layerwise over-smoothing, or task-relevant loss of distinction that this one-dimensional final-target measurement does not capture.

\subsection{Over-Squashing}

The tested prediction is that an exponential increase in directed source-to-target paths forces information from many paths into a fixed-size target representation \cite{alon2021bottleneck}.
Paper~I measures this condition structurally by inspecting the directed generator rather than by inferring it from accuracy.
Each graph contains between $5$ and $10$ alternative chains, and this count does not grow with $d$.
The resulting number of directed paths to the target therefore has a small bound that is independent of the generator parameter $d$ \cite{zhou2025glora}.

Increasing $d$ lengthens the sampled directed paths without producing exponential directed path proliferation in $d$.
Directedness is essential to this observation.
If the edges are symmetrised, message passing can move in both directions, and even one chain can induce exponentially many message-passing walks as depth grows.
The bounded directed-path result excludes exponential directed path proliferation as a complete explanation for the decline in this construction.
It does not exclude sensitivity decay along a path, finite-width limits, task-relative mixing, or optimisation effects.

\subsection{Vanishing Gradients}

The prediction is that vanishing gradients would make the backward signal in early message-passing layers shrink towards zero as the network becomes deeper \cite{glorot2010difficulty}.
Paper~I measures first-layer weight gradients across training epochs for the three diagnostic systems, with training lasting at most $300$ epochs.
Appendix~F reports the same measurement for the second and third layers.

The inspected weight gradients remain stable at magnitudes well above zero in the reported runs \cite{zhou2025glora}.
This observation does not support vanishing weight gradients in the inspected layers as the complete explanation for the performance decline.
Non-zero weight gradients do not prove useful task-aligned gradient transport.
They show that a backward signal reaches the measured parameters, but not that its direction or distribution helps the system learn the intended source-to-target dependency.

\section{Answers Contributed to RQ 2 and RQ 3}

For RQ~2, GLoRa contributes evidence that a benchmark can isolate a specified path-aware dependency while controlling dependency length.
The construction states the source-to-target relation explicitly, while the alternative chains and additional holes address named shortcut functions.
The generator parameter $d$ controls the sampled length range and the dependency guaranteed by Property~(P1), but it is distinct from the realised witness or source-to-target path length in an individual example.
Property~(P1) supplies the sample-qualified guarantee over every fitting node-classification function.
Property~(P2) supplies only an expressibility result: there is a fitting function that all evaluated GNN-based approaches can express; it does not establish learnability.
Property~(P3) supplies Paper~I's class-distribution fairness condition, whereas using the same generated task, data split, validation procedure, and reporting protocol provides system-protocol fairness.
Together, these elements contribute evidence for RQ~2 by making high accuracy stronger evidence that a system uses the intended dependency than in the uncontrolled or shortcut-prone cases identified in Chapter~5.

For RQ~3, GLoRa contributes evidence about how accuracy changes as the generator parameter $d$ and its associated realised path lengths increase, and tests three proposed explanations with measurement-specific diagnostics.
Accuracy deteriorates under the reported protocol.
However, the representation measurement does not show complete collapse of the final target scalar, the directed construction does not exhibit exponential path proliferation in $d$, and the inspected weight gradients remain non-zero.
These diagnostics narrow the three proposed explanations without identifying the mechanism that causes the observed errors.
None supports a universal causal conclusion, so the accuracy trend remains a symptom rather than a diagnosis.

\section{Paper Contribution and Thesis Synthesis}
\label{sec:glora-interpretation}

Paper~I is the thesis's only included paper.
Dongzhuoran Zhou is its first author.
The paper introduces the GLoRa generator, states Properties~(P1)--(P3), evaluates the selected graph learning systems, and reports the three diagnostics \cite{zhou2025glora}.
Those are contributions of Paper~I.

The kappa contributes the surrounding synthesis.
It starts from the distinction between access and demonstrated use in Chapter~3, the mechanism-specific evidence standards in Chapter~4, and the benchmark threats in Chapter~5.
It then separates GLoRa's constructional responses from its theorem, empirical controls, performance evidence, and diagnostic limits.
This separation makes clear what each result establishes and where its support ends.

GLoRa provides controlled evidence for one family of synthetic, path-aware, inductive binary node-classification tasks.
Within that scope, GLoRa shows that many evaluated systems cease to fit the examples reliably as the generator parameter grows, although the intended function remains expressible.
The diagnostics do not observe the specific traces that they test.
This evidence does not provide a universal account of long-range graph learning or a complete causal diagnosis of the observed errors.
At thesis level, GLoRa contributes an evaluation method that links performance across increasing generator parameters to explicit requirements, controls, and evidential boundaries.
