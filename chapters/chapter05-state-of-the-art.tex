\chapter{Evaluating Long-Range Graph Learning}
\label{chap:state-of-the-art}

\section{What Benchmark Evidence Must Establish}

A benchmark result supports only the claims licensed by the benchmark's construction and protocol.
For long-range graph learning, high accuracy must establish more than successful prediction on graphs that contain distant nodes.
The evaluation must connect the score to a stated dependency, control its length, and exclude alternative interpretations of success or failure.
Architecture and intervention families were reviewed in Chapter~4, so this chapter compares evaluations by what their results can establish.

Six criteria define that comparison.
The first three concern whether success demonstrates the intended long-range dependency.
The next two determine whether failure and differences between systems are interpretable.
The final criterion separates a performance symptom from evidence about its cause.

The criteria apply jointly rather than as independent advantages.
A benchmark may specify a distant rule but still admit a shortcut function.
It may exclude shortcuts but require a target function outside the evaluated model class.
A controlled task may also produce a clean accuracy curve without identifying the mechanism behind that curve.
The comparison must therefore distinguish what a result establishes from what the same result leaves open.

\section{Real-World and Synthetic Evidence}

Real-world benchmarks test whether a graph learning system is useful on data from a practical domain.
Their graph structure, features, labels, noise, and sampling process reflect properties that a synthetic generator may omit.
Performance on such data therefore supplies evidence about practical prediction under the benchmark protocol.
It rarely identifies the function that generated the labels, so it usually cannot establish which distant relation a fitted system used.

Synthetic benchmarks answer a complementary question.
Their generators can fix the topology, feature distribution, label rule, graph scale, and distance between relevant nodes.
This control can make a specified dependency and its length observable rather than inferred from domain plausibility.
It can also generate counterexamples in which local and global correlates are held fixed while the intended dependency changes.

Synthetic control is necessary for claims that every fitting function uses a chosen dependency, but it is not sufficient.
A known generator can still produce examples that admit a shortcut function.
It can also define a target that the evaluated model class cannot express or make the classes differ through an unintended construction cue.
Synthetic results therefore require shortcut, expressibility, and fairness analysis in addition to control over the generator \cite{zhou2025glora}.

The two forms of evidence should not be substituted for one another.
Real-world results establish performance on tasks of practical interest, while controlled synthetic results can isolate a known dependency.
Neither type of score diagnoses a failure mechanism without a separate test of the mechanism's predicted trace.

\section{Specified Dependencies and Controlled Length}

A benchmark specifies a dependency when it states which input change can change the correct output and which relation makes that input relevant.
For a path-aware node-classification task, this statement identifies the source node, target node, required intermediate path information, and target label.
The presence of a distant node or a long path is not enough because the label may still be determined by local information.
Likewise, a verbal rule involving distant nodes does not establish that every function fitting the sampled examples uses that rule.

Dependency length is the length of the relation required by the target function.
For the path-aware definition in Chapter~3, it is the exact length $d$ of a witness path $p=(v_0,\ldots,v_d)$.
This quantity is distinct from the shortest graph distance $\operatorname{dist}_G(v_0,v_d)$, the graph diameter, the number of nodes, and the number of message-passing layers.
These quantities may correlate in a benchmark, but none can replace a definition of the dependency length.

A generator parameter also needs a stated interpretation.
If the parameter sets a range of realised path lengths, the evaluation must report that range or distribution instead of treating the parameter as the exact length of every example.
If graph size or density changes with the parameter, the result may combine the effect of dependency length with changes in scale or topology.
Controlled length therefore requires the evaluation to state what varies, what remains fixed, and how the realised examples relate to the claimed dependency length.

Length-indexed evaluation replaces one aggregate score with a performance profile over specified dependencies.
A matched protocol can show where a system succeeds or fails as the required length changes.
Distance-held-out splits can additionally test extrapolation beyond lengths seen during training, whereas in-range splits test performance within the sampled range.
These settings support different claims and should be reported separately.

An accuracy decline over dependency length remains a behavioural symptom.
It can locate a regime for further study.
It does not distinguish strict under-reaching, over-smoothing, over-squashing, optimisation failure, or another cause.
Controlled length makes a trend interpretable as performance evidence, not as a mechanism diagnosis.

\section{Shortcut Resistance}

A shortcut function fits the generated data without using the intended dependency.
This risk arises because a generator rule and the set of functions that fit its sampled examples are different objects.
The rule may refer to a path of length $d$ while a local feature or graph-level statistic predicts every sampled label.
A system that learns the easier function can then achieve high accuracy without demonstrating the intended long-range behaviour.

Shortcut functions can use local features, global counts, graph size, degree patterns, label imbalance, or construction artefacts.
If only negative examples contain a special local marker, a shallow classifier can use that marker.
If graph size separates the classes, a graph-level function can ignore the intended relation.
If a unique structural role identifies the source node globally, the system can read its feature without using the path by which information was meant to travel.

Shortcut resistance requires more than removing one suspected correlate.
The benchmark should name plausible alternative fitting functions and construct examples that make those functions fail.
Paired examples are useful when they preserve reachability and global statistics while changing only the relevant path condition.
A stronger constructional argument establishes that, under its stated sampling conditions, any function fitting enough examples must depend on the specified relation \cite{zhou2025glora}.

Shortcut-prone and inexpressible benchmarks create opposite ambiguities.
On a shortcut-prone benchmark, high accuracy does not establish use of the intended dependency.
On an inexpressible benchmark, low accuracy does not establish a failure to learn an available dependency.
The first ambiguity concerns which fitting function was learned, while the second concerns whether a fitting function exists in the model class.

\section{Target Expressibility and Fair Comparison}

A target function is expressible by a model class when some parameter setting in that class realises the function.
Expressibility is a property of the target and model class, not of a training run.
An expressible target may still be difficult to learn, but an inexpressible target cannot be learned by that class under any optimiser or amount of training.
Low accuracy on an inexpressible target therefore shows a mismatch between the benchmark and model class rather than an isolated learning failure.

The criterion is relative to the systems under study.
A function expressible by one model class may be inexpressible by another because their locality, symmetry, or aggregation constraints differ \cite{barcelo2020logical}.
An evaluation should establish the existence of a fitting function for every class whose failure it interprets.
This general requirement does not assert that training will find the function and does not replace a benchmark-specific expressibility result.

Fair comparison has two separate parts.
Class-distribution fairness requires positive and negative examples to be generated comparably apart from the condition that determines the label.
Graph size, feature counts, path-length distributions, or other generation choices should not become class markers unless they define the target.
This control also supports shortcut resistance because an avoidable class difference can supply an easier fitting function.

System-protocol fairness concerns the comparison between graph learning systems.
The systems should use common data splits, metrics, and evaluation conditions.
Training and tuning budgets should be stated clearly.
Architectural access to inputs should also be reported when one system receives edges, positional information, or global features that another does not.
Such differences may be legitimate, but the resulting score compares both the systems and the information supplied to them.

Fairness does not require every system to have identical hyperparameters or capacity.
It requires a protocol that makes the comparison question explicit and avoids giving one system an unrelated advantage.
Sensitivity to tuning or protocol choices should be reported because a ranking that changes under reasonable choices supports a narrower conclusion.

\section{Existing Benchmark Families Under the Evaluation Criteria}

The reviewed benchmark families support useful but different claims.
The comparison below starts from the evidence each family can supply and then identifies the criteria that remain unsupported.
It does not treat a missing criterion as evidence that the benchmark lacks practical or methodological value.

\subsection{Real-world benchmark families}
\label{sec:sota-real-benchmarks}

TUDataset and OGB both support comparison on shared real-world data, but OGB does so at a larger and more standardised scale.
TUDataset collects graph-classification datasets from several domains and supports comparison between graph kernels and GNNs \cite{morris2020tudataset}.
Its breadth and shared access improve comparability.
The target functions and dependency lengths are not controlled.
Its results can rank systems on the selected datasets without identifying a path-aware dependency.
The Open Graph Benchmark provides larger and more standardised graph learning datasets, public splits, metrics, and tasks \cite{hu2020ogb}.
This scale reduces reliance on the small citation datasets that shaped many early comparisons.
OGB results establish performance under realistic task protocols, but its labels are not designed to certify a dependency of specified length.

LRGB makes long-range capability a more direct comparison target than TUDataset or OGB, but it still does not make a specified path-aware dependency necessary.
The Long Range Graph Benchmark focuses on tasks for which long-range interactions are expected to matter and evaluates systems under a common protocol \cite{dwivedi2022long}.
This focus makes long-range capability a direct comparison target.
The tasks can make distant interaction plausible without proving that every fitting function relies on a specified path-aware dependency.
A later reassessment also found that the reported gap between selected message-passing and GPS baselines depends substantially on tuning and protocol choices \cite{tonshoff2023gap}.
This result sharpens the fair-comparison criterion without removing LRGB's value as a long-range-oriented benchmark.

Taken together, these families support practical and standardised comparison \cite{hu2020ogb,morris2020tudataset,dwivedi2022long,dwivedi2023benchmarking}.
Their results are weaker evidence for a specified dependency because the relevant target function and length are not jointly controlled.
This limitation motivates controlled synthetic evaluation, but does not imply that synthetic results replace real-world evidence.

\subsection{Shortcut-prone synthetic families}
\label{sec:sota-synthetic-benchmarks}

Synthetic Chains, Graph Transfer, and Ring Transfer all make source-to-target separation explicit, but each permits a source-locating shortcut.
Synthetic Chains use directed chains in which a node label depends on information at the start of the chain \cite{gu2020implicit}.
The construction makes source-to-target separation explicit and tests propagation across the chain.
The analysis in \cite{zhou2025glora} identifies a fitting function that ignores distance and path information by locating the unique node without incoming edges and reading its feature.
The benchmark therefore supports a propagation test, but its score does not by itself establish the intended path-aware dependency.
Graph Transfer and Ring Transfer use ring, crossed-ring, or clique-path structures in which a distant target reproduces class information from a marked node \cite{digionvanni2023oversquashing,gutteridge2023drew}.
They support tests of information transfer across an explicit graph distance.
A fitting function can instead locate the globally marked node and transfer its class without using the intended path-aware relation \cite{zhou2025glora}.
Some Graph Transfer settings also contain few distinct examples, which leaves memorisation as an alternative explanation.

Tree-Neighbours and h-Proximity encode different distant conditions, yet neither forces dependence on every relevant path feature.
Tree-Neighbours uses a directed binary tree in which the root must match a leaf selected through a property of one-hop neighbours \cite{alon2021bottleneck}.
The task couples a distant leaf to the root and is not a purely local classification problem.
The analysis in \cite{zhou2025glora} shows that the generated examples can be fitted without relying on the full path-aware dependency.
Its results therefore test a non-trivial tree relation without certifying sensitivity to every required path feature.
h-Proximity uses levelled graphs with red, blue, and uncoloured nodes.
Its target asks whether every red node has at most two blue nodes within an $h$-hop neighbourhood \cite{abboud2022shortest}.
The parameter $h$ makes graph distance explicit.
However, a fitting function need not depend on the features of every node along the paths between the relevant red nodes and the target \cite{zhou2025glora}.
The distance condition does not therefore establish the stronger path-aware dependency.

\subsection{Bounded-length synthetic families}

Conditional Recall and Tree-Max test different computations on bounded structures, so both support claims only over the tested range.
Conditional Recall is a directed-chain task whose nodes encode characters.
Its label is the first item that satisfies a priority rule: a digit if present, otherwise an uppercase letter, and otherwise the first character \cite{lukovnikov2021improving}.
The task tests memory and selection over the generated chains.
Because graph size is bounded, success does not establish a dependency guarantee that extends with an unbounded length parameter \cite{zhou2025glora}.
Tree-Max uses a directed binary tree in which each node is labelled by the maximum digit among itself and its descendants \cite{lukovnikov2021improving}.
A deep descendant can determine an ancestor's label, so the task tests long-range aggregation on the generated trees.
Bounded graph sizes again limit what success can establish about a length-parametrised dependency \cite{zhou2025glora}.

\subsection{An inexpressible synthetic target}

Colour-Connectivity uses two-dimensional grid graphs with red and blue nodes.
The label states whether the red nodes form one connected island or two disconnected islands \cite{rampasek2021hierarchical}.
This target depends on global connectivity rather than a unique marked source.
The analysis in \cite{zhou2025glora} treats the target as genuinely long-range but inexpressible by standard GNN-based systems once the random sample contains enough examples.
Low accuracy can therefore reflect the absence of a fitting function in the model class rather than a failure to learn an expressible long-range dependency.
This limitation is an expressibility problem, not a shortcut diagnosis.

The synthetic families demonstrate why a known long-range rule is not sufficient evidence of demonstrated use.
Chain, transfer, tree, and proximity tasks can contain a clear distant relation while their sampled examples permit another fitting function.
Conditional Recall and Tree-Max test useful computations over bounded structures without establishing a dependency guarantee that extends with length.
Colour-Connectivity presents the opposite problem because the target can require global structure while remaining inexpressible for the evaluated model class.

None of these score types identifies a failure mechanism on its own.
A trend over chain length, tree depth, or neighbourhood radius is a performance symptom.
Diagnostic interpretation still requires a separate test of the task-aligned trace predicted by the proposed mechanism.

\section{Requirements Left Open}
\label{sec:sota-synthesis}

The reviewed families provide practical comparisons and controlled structures.
They also provide explicit distances and useful tests of propagation, memory, aggregation, or connectivity.
The review does not identify one family that jointly establishes all six criteria for a specified path-aware dependency.
Real-world labels leave the required dependency uncertain.
Several synthetic tasks admit alternative fitting functions, control only bounded lengths, or use a target that may be inexpressible for the evaluated class.
The remaining gap is a benchmark and protocol that make four kinds of result interpretable: success, failure, differences between systems, and diagnostic measurements.

The following six requirements therefore define what Chapter~6 must establish for GLoRa \cite{zhou2025glora}.
\begin{enumerate}
\item \textbf{Specified dependency.} Chapter~6 must state the target output and the path-aware relation that a fitting function is required to use.
\item \textbf{Controlled length.} Chapter~6 must vary dependency length under stated controls and distinguish exact witness-path length from any generator parameter.
\item \textbf{Shortcut resistance.} Chapter~6 must show why named local, global, and construction-based shortcut functions cannot fit enough generated examples.
\item \textbf{Target expressibility.} Chapter~6 must establish that at least one fitting function is expressible by the evaluated GNN-based model classes, without treating expressibility as learnability.
\item \textbf{Class and protocol fairness.} Chapter~6 must treat class-distribution fairness and system-protocol fairness as separate controls by making positive and negative examples comparable apart from the target condition and evaluating systems under a common stated protocol.
\item \textbf{Diagnostic interpretability.} Chapter~6 must treat accuracy trends as symptoms and separately measure the task-aligned trace predicted by each proposed failure mechanism.
\end{enumerate}
